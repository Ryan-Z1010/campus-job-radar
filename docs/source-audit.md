为什么不直接全部启用：通用 HTML 爬虫对动态站点可能返回 200，但实际得到的只是空页面框架。这样的“成功”最危险，因为它不会报错，却会漏掉岗位。

每个专用适配器启用前必须验证：

- 连续多次能返回职位；
- 岗位 ID、标题、城市、发布时间、截止日期和详情链接映射正确；
- 空结果与接口故障可区分；
- 请求频率保守；
- 不需要登录、Cookie、验证码或私有凭据。

## 已启用：南航校园招聘

南航官网前端公开使用：

- `GET /api/front/findPositionTypes` 获取招聘类型；
- `POST /api/front/findPositions` 获取岗位；
- `jobType=3` 表示校园招聘。

2026-07-24 验证时，校园招聘返回 0 个岗位；用社会招聘分类做只读连通性
验证时返回 4 个广州岗位。项目配置始终固定为 `jobType=3`，不会把社会
招聘混入校招提醒。

## 已启用：南方电网公开岗位

南方电网招聘官网对未登录访客执行公开的 `guestLogin` 流程：

- `POST /authLoginParam/guest/getGuestToken` 创建短期匿名会话；
- 使用该匿名令牌 `POST /webPost/search` 查询岗位；
- 搜索参数、字段映射和岗位详情路由均来自官网当日公开前端代码。

适配器不会模拟账号登录，也不保存匿名令牌。令牌仅在一次采集过程中保留
在内存里。2026-07-24 真实验证时，接口正常返回 `code=200`，当前岗位总数
为 0；这被视为“官网当前没有公开岗位”，与 401、结构变化或网络错误明确
区分。

## 已启用：中国移动 2027 正式校招公告监控

中国移动招聘官网首页公开读取
`/personal/notice/5044401_11161_21137.json` 展示招聘公告。该静态 JSON
无需账号、Cookie、验证码、私有令牌或请求签名，列表包含公告标题、招聘
单位、发布时间、截止时间和官网详情链接。

项目已用 `notice_json` 接入该列表：

- 只匹配 `2027校园招聘`、`2027届校招` 等正式校招届别；
- 排除实习、社会招聘、拟录用和录用结果，避免把暑期实习误报为秋招；
- 每条匹配公告保留官网公告 ID、发布时间、截止时间和详情链接；
- JSON 结构变化会产生来源错误，而当前没有匹配公告会正常返回空结果。

2026-07-27 真实验证时，公开列表返回 74 条历史及当前公告，最新内容包括
社会招聘结果、系统升级和 2026 春招；尚无 2027 正式校园招聘公告，因此
监控结果为 0 条。中国移动职位明细页仍使用带摘要签名的动态请求，本项目
不复制该签名机制；若后续出现稳定公开岗位接口，再升级为岗位级采集。

## 已启用：中国联通广东省分公司岗位级监控

秋招追踪表中，中国联通广东省分公司同样属于“广州 + 央企 + AI/数据方向”

岗位职责、首次发布时间和投递截止时间，不需要登录、Cookie、验证码或
请求签名。

2026-07-27 真实验证时，页面共有 2 个广州校园岗位：数据开发工程师和运营
经理。两条记录的 `firstPublishTime` 都是 2025-08-28，属于上一招聘周期；
虽然页面仍在更新和展示，但不能据此判断 2027 秋招已经开始。因此项目：

- 只保留 `firstPublishTime >= 2026-07-01` 的校园岗位；
- 再按 AI、人工智能、数据、大数据、云计算、算法、开发、数字化等关键词
  筛选，并排除销售、客服和营业岗位；
- 使用公开公司页作为核对及投递入口，不猜测职位详情 URL；
- 当页面声明的岗位总数大于 HTML 内实际岗位列表时报告来源错误，提醒后续
  接入稳定公开分页接口，避免静默漏岗。

当前真实采集结果为 0 个 2027 周期匹配岗位，这是正常的“尚未发布”，不是
采集失败。新岗位首次发布后，会进入统一去重、评分和邮件提醒流程。
